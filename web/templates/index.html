Comparing Two Ways of Finding Information in Patient Records

Medical records contain important information in tables, reports, and records from different dates. When these records are split into small text pieces, some information can become separated from its headings and related details.

Our project compares two approaches to finding information in synthetic patient records. The first approach searches through smaller text pieces. The second preserves document structure and uses a manually created knowledge graph to connect related medical information.

This Phase-I project uses five synthetic patient records and 50 questions to test how both approaches retrieve and present information. The results are preliminary and are evaluated using custom measurement methods with known limitations.

How Pipeline B Works

Three Key Techniques Used in Pipeline B

How preserving document structure, using a manually created knowledge graph, and checking citations helps retrieve reliable medical information.

01 · Preserving tables

Keeping Tables & Flowsheets Intact

Standard splitting breaks markdown tables into pieces. Our parser keeps entire tables together with their column headers so critical flags (like Potassium 5.7 CRITICAL_HIGH) stay attached to their test names.

Structure-Preserving Table Parser
02 · Connecting facts

Following Connections Across Visits

Basic text search can miss connections that are days apart. A manually created knowledge graph links related facts across multiple visits—connecting a Day 1 Lisinopril prescription to a Day 7 Acute Kidney Injury (AKI).

In-Memory Knowledge Graph (Manually Created for 5 Records)
03 · Checking sources

Step-by-Step Answer Checking

A step-by-step workflow checks if retrieved text is relevant. It formats the answer based on retrieved facts and attaches exact document and page citations so every statement can be checked.

Deterministic Step-by-Step State Machine
Pipeline B Workflow

4-Stage Step-by-Step Search Process

A controlled, predictable process in Python that finds information, checks relevance, and attaches source citations without endless loops.

Stage 1: Identify Key Terms
Extracting Medical Terms & IDs
Isolates patient identifiers (like P-101, a fictional patient identifier), medication names, dates, and target lab test names from the query.
Stage 2: Search Text & Graph
Combined Text and Graph Search
Searches document sections using keyword matching while simultaneously looking up connected medical facts in the in-memory knowledge graph.
Stage 3: Check Relevance
Checking Retrieved Information
Checks whether the retrieved text contains enough matching information. If relevance is low, it tries at most one query rewrite using medical synonyms.
Stage 4: Verify and Cite
Answer Assembly & Citation Attachment
Constructs the answer using the retrieved evidence and attaches exact document and page citations so every statement can be verified.
